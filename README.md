## Project Overview

This lab series demonstrates five common machine-learning workflows. The first four exercises use supervised learning to predict a numeric target or a class label. The fifth uses unsupervised learning to group wholesale customers according to spending patterns.

## Exercise 1 — Multiple Linear Regression: Insurance Cost Prediction

### Goal
Predict individual insurance charges from demographic and health-related attributes in the insurance dataset.

### Data and features
The notebook uses fields such as age, BMI, number of children, sex, smoking status, and region. The target variable is `charges`.

### Workflow
1. Load and inspect the dataset, including its shape, missing values, and target distribution.
2. Scale numeric predictors such as age, BMI, and children.
3. One-hot encode categorical predictors, using a dropped reference category where specified.
4. Split the dataset into training and test subsets with a fixed random seed.
5. Fit a linear regression pipeline and generate predictions on held-out data.
6. Inspect model coefficients and residuals. The notebook also compares a log-transformed target as a benchmark.

### Evaluation
- **R²:** measures the proportion of target variance explained by the model.
- **RMSE:** expresses typical prediction error in the target's original units; lower is better.
- **Residual analysis:** helps identify systematic errors and non-constant error variance.
- **Coefficient interpretation:** estimates how predictors relate to expected insurance charges, conditional on the other model inputs.

### Acceptance checks
The lab benchmark specifies **R² ≥ 0.75** and **RMSE < 4,800**. Use the latest executed notebook output to determine whether both checks pass.

### Deliverables
The executed notebook, prediction CSV (actual values, predicted values, and residuals), plots, and a short interpretation of model performance.

## Exercise 2 — Logistic Regression: Direct Marketing Conversion

### Goal
Predict whether a person subscribes to a term deposit in the UCI Bank Marketing dataset.

### Data and features
The target column `y` is mapped to binary labels: `no → 0` and `yes → 1`. Predictors in the notebook include age, job, balance, duration, campaign, and poutcome.

### Workflow
1. Load the Bank Marketing CSV and inspect class balance.
2. Create a stratified train/test split so the class ratio is represented in both subsets.
3. Apply robust scaling to selected numeric variables, standard scaling to other numeric variables, and one-hot encoding to categorical variables.
4. Fit logistic regression with class weighting to account for the imbalanced target.
5. Generate predicted probabilities and apply the notebook's stated decision threshold.
6. Review the classification report and confusion matrix.

### Evaluation
- **ROC-AUC:** measures how well the model ranks positive cases above negative cases across thresholds.
- **Recall:** measures the fraction of actual subscribers correctly identified.
- **Precision and F1:** provide additional context on false positives and the balance between precision and recall.
- **Confusion matrix:** shows correct and incorrect predictions by class.

### Acceptance checks
The lab benchmark specifies **ROC-AUC ≥ 0.78** and **Recall ≥ 0.70** at the stated threshold. Confirm the numeric recall value from the latest run; a Boolean pass flag is not a substitute for the metric itself.

### Deliverables
Notebook outputs, classification metrics, confusion matrix, and a CSV containing actual labels, predicted probabilities, and threshold-based predictions.

## Exercise 3 — Decision Trees: Interpretable Rules

### Goal
Build an interpretable classification model and translate its decision paths into readable IF–THEN rules.

### Data and approach
This exercise uses the Bank Marketing predictors and target introduced in Exercise 2. It explores tree criteria and compares a less constrained tree with a constrained/pruned tree.

### Workflow
1. Prepare the transformed feature matrix and retain readable feature names.
2. Compare Gini and entropy criteria where specified in the notebook.
3. Demonstrate how an unconstrained tree can become overly complex.
4. Train a constrained tree using the lab's limits, including a maximum depth of five and minimum sample constraints.
5. Inspect the tree visualization and exported text rules.
6. Translate selected paths into IF–THEN statements and explain their business meaning.

### Evaluation
- **Accuracy:** fraction of test records classified correctly.
- **Tree depth:** a simple measure of model complexity and interpretability.
- **Rule interpretation:** connects split conditions to understandable patterns in the data.

### Acceptance checks
The lab benchmark specifies **accuracy ≥ 0.85** and **tree depth ≤ 5**. The actual reported accuracy and final fitted tree depth should be checked after execution.

### Deliverables
Tree plots, exported rules, evaluation metrics, and a brief explanation of selected business rules.

## Exercise 4 — Random Forest: Ensemble Learning

### Goal
Use a Random Forest to improve classification through an ensemble of decision trees and examine which features contribute to predictions.

### Workflow
1. Prepare a Random Forest-specific feature matrix and preprocessing pipeline.
2. Include the lab-highlighted predictors such as `duration`, `pdays`, and `age` where they are available in the selected feature set.
3. Fit candidate models using a grid search over tree count, feature sampling, tree depth, and class-weight settings.
4. Use cross-validation on training data to select model settings.
5. If a probability threshold is tuned, choose it using a validation subset of the training data rather than the held-out test set.
6. Refit the selected model on training data and evaluate once on held-out test data.
7. Inspect impurity-based and, where included, permutation feature importance.
8. Export test predictions and their predicted probabilities.

### Evaluation
- **Out-of-bag (OOB) score:** estimates performance using training examples omitted from individual bootstrap samples.
- **F1 score:** combines precision and recall, useful when positive examples are less common.
- **ROC-AUC:** measures ranking performance across classification thresholds.
- **Feature importance:** provides a model-specific indication of which inputs contributed to predictions; importance is not proof of causation.

### Acceptance checks
The lab benchmark specifies **OOB ≥ 0.88** and **F1 ≥ 0.65**. Report both values from the same final model/evaluation run. If F1 remains below target, document the shortfall rather than changing the reported score.

### Deliverables
Selected model settings, OOB and test metrics, feature-importance analysis, classification report, and prediction CSV.

## Exercise 5 — K-Means: Wholesale Spending Personas

### Goal
Group wholesale customers by purchasing patterns across six spending categories and describe the resulting segments.

### Data and features
The UCI Wholesale Customers dataset contains annual spending fields. The clustering uses:
`Fresh`, `Milk`, `Grocery`, `Frozen`, `Detergents_Paper`, and `Delicassen`.

### Workflow
1. Load the dataset and select the six spending features.
2. Apply `log1p()` to reduce the influence of strongly skewed spending values.
3. Apply `StandardScaler` to place transformed features on a comparable scale.
4. Compare candidate cluster counts from **k = 2 to k = 8** using inertia (the elbow method) and silhouette score.
5. Fit the required reference model with **k = 4**.
6. Summarize cluster means using the original, unscaled spending values so the profiles remain interpretable in spending units.
7. Translate each cluster into a cautious commercial persona based on its spending profile.

### Evaluation
- **Inertia / WCSS:** measures within-cluster squared distances; it generally decreases as more clusters are added.
- **Silhouette score:** evaluates how close points are to their own cluster compared with other clusters; higher values indicate better-separated clusters.
- **Cluster profiles:** compare mean spending by category to help describe the groups.

### Acceptance check
The lab benchmark specifies **silhouette score ≥ 0.42 for k = 4**. Preserve the specified preprocessing and report the actual score. Alternative feature subsets or cluster counts may be described as exploratory analyses, but should not replace the required reference result without clearly identifying the change.

### Deliverables
Elbow and silhouette plots, cluster assignments for each customer, centroid/profile CSV, and four written persona descriptions.

## Evaluation and Limitations

- Results depend on the exact dataset file, preprocessing, split, random seed, and library versions.
- A passing training or validation score does not guarantee a passing held-out test score.
- Threshold selection should be performed on training/validation data, not repeatedly optimized against the test set.
- A benchmark target that is not met must remain marked as not passed until a defensible model change produces a verified result.
- The README describes the intended workflow; it does not claim that every benchmark passed unless the latest executed acceptance summary confirms that status.
